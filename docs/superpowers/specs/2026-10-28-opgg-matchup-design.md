# 选人阶段 OP.GG 对位分析内页设计

状态：2026-10-28 用户以“就这么做”确认完整设计；已在功能分支实现。离线真实组件演示、单元测试、构建和独立代码审查已完成。2026-10-29 需求方确认已实机使用且效果很好，并授权提交 PR 邀请维护者试用；尚未合入上游，逐项异常场景与其他平台验收仍需补充。

## 目标与背景

在腾讯国服客户端的选人阶段，根据公开可见的敌方英雄提供候选英雄的对位参考。数据使用 OP.GG，不采用或降级到国服排行榜。当前电脑没有英雄联盟客户端，需要独立演示和可重复测试，真实客户端联调另行验收。

仓库为 `wnzzer/rank-analysis`，MIT 协议；分支 `feat/opgg-matchup-panel`，基线 `3878348`。不继承旧英雄大全分支。相关需求为 GitHub Issue #189。

项目已有 Vue 3 / TypeScript / Naive UI / Rust / Tauri 2、OP.GG 基础快照、头像资源协议和 `docs/superpowers/specs` 设计流程。本期沿用现有流程，不另行初始化 OpenSpec，不升级框架或引入动画库。

## 已选方案与替代方案

- **A：敌方队伍区域增加局部内页，已选。** 原阵容列表为一级页面，对位分析为二级页面。只有敌方区域发生转场，我方、顶部信息与原有操作不移动。返回恢复原列表位置与状态。
- B：右侧覆盖抽屉。空间独立，但遮住敌方阵容并产生额外关闭负担，未采用。
- C：卡片内展开。关联直接，但长列表会推移其他英雄卡片，未采用。

## 原有功能保留约束

本期是增量内页，不重做或精简选人页。必须保留阶段提示、游戏类型、OP.GG 版本与原段位控件、双方禁用、BP 决策带、符文/出装推荐栏、设置与 AI 分析入口，以及原玩家卡/匿名英雄卡的全部内容和交互。原组件的显示条件、数据订阅与业务动作保持原有语义。

有战绩的敌方 PlayerCard 在右侧「近期数据」框下方独立增加「对位分析 · 英雄名 ›」按钮，明确目标是本局已亮出的英雄，不是召唤师个人胜率，也不是历史对局格子里的英雄。不改头像、玩家名及历史对局原有点击语义，不挤占标签区。PlayerCard 增加可选操作插槽，SubteamCard 注入入口；我方不注入。无身份的 ChampionIntelCard 在紧凑卡片尾部提供同一语义入口。加载/战绩隐藏但已知本局英雄时仍可通过英雄入口分析，不依赖个人战绩获取成功。

右侧队伍标题行固定增加「玩家战绩｜英雄对位」两种局部页面入口；默认玩家战绩，英雄对位在尚未选择分析目标时禁用并提示从卡片进入。卡片按钮选择该槽位/英雄并切换到英雄对位；之后顶部入口可在两个页面之间切换，明确告诉用户当前看的是什么。只有右侧内容暂时切换为统计内页，五人的原战绩保留在一级页面；不承诺同时展示完整双页面。内页返回文案为「返回玩家战绩」。

原敌方列表在内页期间保留组件实例及滚动状态，仍接收会话更新；隐藏区域设为 inert 和 aria-hidden，不能被键盘访问。返回恢复点击入口的焦点，入口因换人消失时回到敌方区域标题。顶部和我方组件不得随内页开合卸载。

## 交互与视觉

### 进入和返回

点击入口进入内页，不悬停自动打开、不添加全屏遮罩，不跳转召唤师详情或 OP.GG 网站。内页顶部为「玩家战绩 / 英雄对位」层级与返回按钮，其下保留五个敌方英雄的头像切换入口。未选英雄为占位且不可选；正在预选的英雄标记「选择中」而非已锁定。只有明确的「查看 OP.GG」来源链接才打开外部网站。

切换目标不会再次执行整个内页进入动画。目标、分路、段位变化只刷新相关内容。关闭后可重新打开，保留本次会话最近目标和筛选；会话结束清空目标/位置修正，下一局不得沿用上局槽位。会话离开 ChampSelect 时退出内页并撤销过时请求的渲染资格。

槽位与英雄共同标识目标。换英雄时更新头像/名称并重新查询，清除该槽位之前英雄的手动分路；变为未选时保留区域并提示等待，不把旧英雄数据挂到新英雄下。

### 信息层级

1. 返回入口与敌方五英雄切换。
2. 目标头像、英雄名、位置来源（推测/手动）、分路选择。
3. **明确可见的段位筛选**，与数据地区及来源一起呈现。
4. 「推荐应对」「谨慎选择」两个列表视图。
5. 候选行包含 **真实英雄头像 + 中文名**、整场对位胜率、线杀率、样本数；小样本说明靠近样本数字。
6. 底部显示实际版本、数据更新时间、过期状态与 OP.GG 原始页面入口。

首屏重点是候选而不是大号装饰标题。数字右对齐、等宽数字；颜色配文字，不只用红绿判断。加载时保留筛选与布局高度，行级骨架或占位，禁止显示旧筛选的数字却冠以新筛选名称。空数据/失败都提供可理解的原因；失败可重试，重复请求合并。

### 段位

复用 `TIER_OPTIONS`：黄金以上、铂金以上、翡翠以上、钻石以上、大师以上、全部段位。界面明确为“以上”统计集合，不冒充纯单段位。默认读取现有配置，默认值翡翠以上。

对局页 `Gaming.vue` 持有唯一的 `useOpggTier()` 状态；原页面控件与内页控件通过同一个值和切换事件同步，内页不再另建一个独立配置状态。保持现有设置页关联与持久化语义。切换会影响本页已有 OP.GG 信息，控件提示「与本页 OP.GG 数据同步」。

切换过程中控件显示加载并禁止重复提交，返回按钮和目标切换仍可用。复用并验证原 `switchTier` 的失败回滚；只有确认返回快照的实际段位一致，才提交新的当前段位并加载该段位的对位数据。对位请求额外显式携带 tier，并校验返回上下文；旧段位响应即使后到也不能覆盖当前结果。

### 头像与资源

正式组件使用 `useAssetUrl().getChampionUrl(id)` 与项目中文英雄名服务，复用已有缓存与资源协议，不把外部图片 URL 散落在产品代码里。候选头像约 32px，目标约 40px。保留固定宽高，失败用项目占位风格和名字兜底，避免破图、布局抖动、无限重试。示意页面可使用 Riot 公共头像；演示与正式资源获取分开标明。

### 动效

使用项目 `--dur-fast`（150ms）、`--dur-normal`（250ms）及 easing 变量，内页进入/返回为方向相反的 8px 横移与透明度过渡，原页面不发生宽高伸缩。只对可见敌方区域应用，不重新播放整页动画。

目标切换采用约 150ms 的局部内容淡入；列表页签用滑动选中底线/背景表达切换，不让整页重新滑动。头像边框、入口箭头和按钮颜色自然过渡。数值不滚动、不计数动画，避免误读；加载不用持续闪烁整页。高频切换采用最新状态，不排队播放过时动画。

`prefers-reduced-motion` 时取消位移/模糊/骨架脉冲，状态仍立即、清晰可辨；键盘焦点可见。关闭支持 Escape，但下拉或更上层已有弹窗正在处理 Escape 时不得同时关闭本内页。

## 数据来源和统计契约

已通过实际请求核查 OP.GG 完整对位接口；它是网站数据接口，结构变化应转为可识别的不可用状态，不伪造结果。

- 列表：`https://lol-api-champion.op.gg/api/global/champions/ranked/{enemyId}/{position}/counters?tier={tier}&version={version}`。
- 双方详情：在 counters 后加 `/{candidateId}`，同样携带 tier/version。
- `version` 参数有效；不能用被服务端忽略的 `patch`。先发现当前版本，之后同轮查询锁定该版本，返回版本不符视为不可合并。
- 列表 `data[].champion_id/play/win` 的 win/play 是 URL 主体（敌方）的整场胜率。它是接口提供的完整位置候选集，不承诺全英雄池。
- 推荐应对：敌方列表胜率低于 50%，按敌方胜率从低到高；谨慎选择：高于 50%，从高到低。恰好 50% 不列入两边。列表旁注明排序依据。样本不足 200 局的候选放在同组尾部并标记小样本，该阈值是本项目提示规则，不声称 OP.GG 标准。
- 展示给用户的候选胜率必须取双方详情中 `champion_id === candidateId` 的 `win/play`，不能 `1 - enemyRate`。列表排序的源样本与详情可能不同；详情返回后不静默重排列表，行内数值及样本以该详情为准。
- 线杀率取双方 `lane_kill` 归一化，`candidate.lane_kill/(candidate.lane_kill+enemy.lane_kill)`，不使用 `lane_solo_kill`。按官方定义是对线阶段击杀或助攻相关比例，并非单杀率。
- 打野线杀率显示「不适用」，即使接口含数字也不显示成线杀率。
- 缺任一方、零分母、非法计数或版本不一致显示「暂无数据」，不补 0%/50%。计数需有限、非负，胜场不得超过样本数；零胜场且样本大于零是有效 0%。
- 页面标明全球数据、段位、位置、版本；使用该数据自身的缓存时间，不把本地请求时间冒充统计更新时间。双方详情样本/更新时间与列表不同可在详情提示中说明。

本期仅适用传统双队召唤师峡谷选人；大乱斗和多队模式不提供常规分路对位内页。敌方位置若无可靠公开分路信息，采用英雄最常见位置并标记推测，可手动改，绝不以敌方列表顺序推断确定分路或索取隐藏身份。

## 推荐边界与请求调度（实施者选择）

本期为只读数据参考，不改自动选人/禁用/符文逻辑，不自动锁英雄。已禁用、队友已选、敌方已选等公开可见限制在候选行标注并弱化；保留数据阅读。英雄拥有状态未知时不声称可用，不新增客户端购买或锁定动作。

列表完整获取；每页最多 8 个候选，对当前页获取双方详情，并发最多 3。同键请求合并。缓存键包含地区、模式、版本、段位、分路、敌方和候选 ID；缓存有效期暂定 30 分钟。网络失败可用同键旧缓存，必须显示过期时间和重试，不能跨段位/版本回退。快速切换用请求序号/上下文校验，过时结果可进入对应缓存但不能进入当前视图。

不一次并发请求全部候选，不在选人会话每个事件重复取数，不在渲染器直接跨域抓网页。Rust 负责 HTTP、超时、验证与缓存；前端负责筛选状态、呈现与反馈。

## 模块边界与实施顺序

1. **数据层**：在现有 `src-tauri/src/opgg` 增加独立 matchup 模块与 DTO，在 command/opgg 注册只读命令；不改变旧 top3 counter 契约。固定样本测试解析、方向、零值、版本和缓存隔离。
2. **前端服务**：新增对位类型与服务包装、查询 composable；错误与空结果区分。复用 tier 和头像基础设施，避免把整套逻辑堆进 Gaming.vue。
3. **新增内页**：新增 MatchupPanel 与候选行组件，外层 SubteamCard 控制局部一级/二级页面；Gaming.vue 传递共用段位和选人限制。保留原卡片树，只增加入口与局部转场。
4. **无客户端演示**：独立开发入口注入模拟会话和明确标记的固定对位样本，复用正式展示组件；模拟成功、慢响应、空数据、失败、换人和段位切换。另用真实 OP.GG 请求验证数据适配层，二者结论分开记录。演示入口不绕过正式客户端连接检查，不进入正常产品导航。
5. **验收与交付**：本地分支可供自用；维护者同意后另行准备 PR。保持 MIT 版权及许可证。若打包自用，先验证本地版本/更新行为避免被正式自动更新覆盖，不擅自关闭用户已有安装更新。

## 项目代码规范

沿用 `CLAUDE.md`、`CODE_QUALITY.md`、既有命名/目录/主题与测试工具。新增方法、类型、字段补齐准确中文 JSDoc/RustDoc；统计方向、缓存键、状态失效、动效生命周期写明原因。修改保持小范围，避免无关格式化和重构。

原生检查包括 `npm run check`、相关 Vitest 和 Rust 单测；以实际 package 配置确认具体命令。没有可用 JetBrains 连接时使用项目原生工具，不把草图测试当产品测试。
