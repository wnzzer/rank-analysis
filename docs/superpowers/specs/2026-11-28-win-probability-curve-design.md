# 复盘胜率曲线与关键转折（ΔWP 阶段 1）设计

日期：2026-11-28

## 背景

评分消融（2026-11-28，106 条线上玩家标注）显示：现行手工权重评分与玩家判断一致率 51%，与朴素 KDA（53%）无显著差；玩家判断本身受计分板偏向影响，作为唯一标尺不可靠。胜率模型（win probability, WP）有客观验收标准（留出局 AUC、校准），可作为新评分方式的起点。

阶段 0（离线原型，Node，`scratchpad/wp/`）已验证可行：基准语料 9220 局排位、逻辑回归（特征 × 时间交互），留出 1821 局 AUC 10 分 0.774 / 15 分 0.854 / 25 分 0.924，十档校准误差 ≤ 3 个百分点；Top |ΔWP| 窗口落在真实的团战 / 资源上。

本设计是阶段 1：**对局层面**的胜率曲线与关键转折，不涉及个人评分。阶段 2（按参与度把 ΔWP 分给个人）不在本期范围。

按项目「重 Rust 轻 Node」的取向，特征、推理、转折点选择、文字拼接、训练全部在 Rust；TS 只渲染。

## 范围

做：

- Rust 胜率模块：特征抽取、推理、转折点选择与文字
- `get_match_timeline` 的返回值带上胜率结果
- 复盘页「经济差曲线」组件加「胜率 / 经济差」切换与转折点标记
- Rust 离线训练程序（`cargo run --example`），产出编译进 app 的系数文件

不做：

- 个人层面的 ΔWP 分配（阶段 2）
- 把转折点喂给 AI 复盘（以后单独一期，需改提示词并重跑 A/B）
- 我方视角（统一蓝方视角，与现有经济差曲线一致）
- 记住用户上次选的模式

## 架构

### Rust 模块 `src-tauri/src/win_prob/`

| 文件 | 职责 |
|---|---|
| `features.rs` | `SlimTimeline` → 每分钟特征（蓝 − 红） |
| `model.rs` | 加载 `include_str!("model.json")`，特征 × 时间交互后逻辑回归推理 |
| `turning.rs` | 从曲线选转折点并拼文字 |
| `mod.rs` | 对外唯一入口 `analyze(&SlimTimeline) -> Option<WinProbability>`，以及 `FEATURES` 常量 |
| `model.json` | 训练产物：特征名、标准化参数、权重、元信息 |

**特征（16 个，均为蓝方 − 红方，取每分钟帧时刻的累计值）**：金币（/1000）、经验（/1000）、补刀（小兵 + 野怪，/10）、击杀、推塔、水晶、镀层、小龙（不含远古龙）、远古龙、大龙、先锋、虚空巢虫、阿塔坎、大龙 buff 在身（击杀后 180 秒）、远古 buff 在身（击杀后 150 秒）、龙魂点（3 条小龙 = 1，≥ 4 条 = 2）。

不用「快照时刻存活人数差」：阶段 0 验证它让曲线来回抖（去掉后反转少 37%，只损 35 分 AUC 0.887 → 0.871）。

**模型**：设计矩阵 = [1, m, x₁, x₁·m, …, x₁₆, x₁₆·m]，m = 分钟 / 30；标准化后逻辑回归。`model.json` 记录 `features` 名单，加载时与 `FEATURES` 常量逐项比对，不一致视为模型不可用。

**输出结构**（挂在 `SlimTimeline` 上，camelCase 序列化）：

```rust
pub struct WinProbability {
    /// 每分钟蓝方胜率 0~1；blue[i] 对应第 i+1 分钟帧
    pub blue: Vec<f32>,
    /// 最多 3 个，按时间升序
    pub turning_points: Vec<TurningPoint>,
}

pub struct TurningPoint {
    /// 窗口 (minute-1, minute] 分钟
    pub minute: u32,
    pub from: f32,
    pub to: f32,
    pub text: String,
}
```

`SlimTimeline` 新增 `#[serde(default)] pub win_probability: Option<WinProbability>`。

### 转折点规则（确定性）

1. 候选：相邻两分钟蓝方胜率变化 |Δ| ≥ 0.10。
2. 过滤快照抖动：下一分钟回吐超过该变化的一半则丢弃（最后一分钟不做此检查）。
3. 按 |Δ| 降序挑选，与已选点间隔 < 2 分钟的跳过，最多 3 个；结果按时间升序。

**文字**（只拼数据里有的事实，事件按时间戳落入窗口 (minute-1, minute]，不按帧下标——第 0 帧不产出胜率点）：

- 双方击杀合计 ≥ 3：「团战{人头多的一方} X 换 Y」（X 为该方击杀数，平局以蓝方开头，如「团战红方 4 换 0」）；否则有击杀时写「蓝方击杀 X、红方击杀 Y」（为 0 的一侧省略）
- 建筑：「蓝方推掉 N 座塔」「红方推掉 N 座水晶」等（按推掉方归类）
- 资源：「蓝方拿下小龙 / 远古龙 / 大龙 / 先锋 / 虚空巢虫 / 阿塔坎」；同方同类资源在窗口内多次只写一次，次数 > 1 时加「×N」（如「拿下虚空巢虫×3」）
- 窗口内无上述事件：「经济差拉开」
- 片段用「，」连接，句末不加标点；胜率数字由前端渲染，不进 `text`

### 数据流

1. 前端照旧调用 `get_match_timeline`。
2. Rust 读缓存或拉 SGP 得到 `SlimTimeline`。
3. **每次返回前**都调用 `win_prob::analyze` 重新计算并覆盖 `win_probability`（缓存里的旧值或缺失一律不用），模型重训后不会读到过期结果。缓存版本 `CACHE_VERSION` 不变。
4. 前端只渲染。

适用范围：Rust 侧拿不到队列（command 入参只有大区和 gameId），只要数据完整就计算；**是否显示**由前端按已有的 `modeContext.hasLanes` 决定，大乱斗 / 斗魂竞技场等不显示切换。

### 错误处理

胜率出任何问题都不能影响时间线本身。

| 情况 | 处理 |
|---|---|
| 任一帧玩家数 ≠ 10 | `None`，`log::debug!` |
| 分钟帧数 < 5 | `None` |
| `model.json` 解析失败或特征名不一致 | `None`，进程内只 `log::warn!` 一次；单元测试保证入库的模型可用 |
| 前端拿到 `None` / 字段缺失 | 不显示切换，只有经济差曲线（与现状一致） |

## 前端（`GoldCurve.vue`）

- 标题栏右侧加分段按钮「胜率 / 经济差」；有胜率数据时默认「胜率」；没有数据时不出现按钮。
- 胜率模式：纵轴 0~100%，中线 50%（复用零线居中布局）；标题「胜率曲线（上 = 蓝方占优）」；图例加「你在红方 / 蓝方」（拿不到本人时不显示）；悬停显示「第 N 分钟 · 蓝方胜率 x%」。
- 原有团战 / 资源 / 阵亡标记两种模式都显示，位置不变。
- 转折点（仅胜率模式）：该分钟半透明竖向色带，对蓝方有利为蓝、对红方有利为红；顶部徽标写幅度（如「+25」）；点击或悬停徽标弹出「{text}。蓝方胜率 49% → 74%」。
- TS 只给 `SlimTimeline` 类型加可选字段 `winProbability`；基准构建用的 TS 时间线裁剪移植不改。

## 训练程序 `src-tauri/examples/train_wp.rs`

- 运行：`cargo run --release --example train_wp -- --corpus <DETAILS 目录> --out src/win_prob/model.json`，语料默认 `../scripts/baseline/raw/details`（`.json.gz`；新增 dev-dependency `flate2`，不进安装包）。
- 流程：原始 DETAILS → `slim_from_raw` → `win_prob::features`（与 app 同一份代码）；标签取 `GAME_END.winningTeam`；不足 10 分钟帧的局跳过。
- 训练：逻辑回归，全批量 Adam，L2 = 1e-4，`gameId % 5 == 0` 为留出集；不用随机数，同一语料结果可复现。
- 产物 `model.json`：`features`、`mu`、`sd`、`weights`、`meta`（训练时间、局数、版本范围、5/10/15/20/25/30/35 分钟 AUC、最大校准误差）。
- 验收门槛（不达标非零退出、不写文件）：留出 15 分钟 AUC ≥ 0.84，十档校准最大误差 ≤ 0.05。
- 一次性对拍（开发时，不进 CI）：与 Node 原型 `scratchpad/wp/train.mjs` 同口径下 AUC 差 ≤ 0.005。
- 重训时机：大版本后随评分基准一起重采语料、重训。

## 测试

Rust（`cargo test`）：

- `features`：用 `tests/fixtures/sgp_details_sample.json` 经 `slim_from_raw`，断言某分钟金币差 = 逐人求和结果、推塔事件后塔数差变化正确、远古龙不计入小龙
- `model`：入库 `model.json` 可加载且特征名一致；其余特征为 0 时金币差越大胜率越高
- `turning`：人造曲线——|Δ| < 0.10 不选、回吐过半丢弃、间隔 < 2 分钟只留大的、最多 3 个且按时间升序；文字——团战阈值、建筑与资源名称、「经济差拉开」兜底
- `analyze`：帧数 < 5、某帧非 10 人返回 `None`

前端（vitest）：有数据默认胜率且可切换；`None` 时无切换按钮；转折点徽标数量与颜色；切换后原有标记仍在。
