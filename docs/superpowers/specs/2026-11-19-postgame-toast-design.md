# 赛后右下角弹卡设计

日期：2026-11-19
状态：已实现（随 #206 一起提交）
依赖：#206 赛后战报图（复制按钮复用 `ShareCard` / `services/shareCard.ts`）；本次也一并升级了战报图视觉

## 目标

赛后战报（#204）和战报图（#206）都放在对局页里，可玩家打完一局时眼前是 LOL 客户端，我们的窗口在后面，
**漏斗第一步「被看到」就漏掉了**。这次在屏幕右下角（托盘附近）弹一张小卡片，WeGame 那种形式，
在玩家情绪最高的结算时刻把人带进标注和分享。

打点要能回答的问题：弹卡展示以后，标注率和战报图复制率比现在高多少。

### 不做的事（V1）

- 不做系统托盘图标和「关闭到托盘」：这里只是借用托盘附近这个位置，托盘以后单独做。
- 弹卡里不放完整的标注卡和战报图：卡上只放钩子，真正的操作还在主窗口里做。
- 不覆盖匹配 / 大乱斗等队列：和战报一样只做 420 / 440。

## 什么时候弹

| 条件                                                                | 行为                               |
| ------------------------------------------------------------------- | ---------------------------------- |
| 阶段进入 `PreEndOfGame` / `EndOfGame`，队列 420 / 440，本局还没弹过 | 弹                                 |
| 主窗口当前是前台、已经可见                                          | 不弹（玩家已经看得到对局页的战报） |
| 设置「赛后弹卡」关闭                                                | 不弹                               |
| 进入 `ChampSelect` / `Matchmaking`（开下一局）                      | 立刻关                             |
| 弹出 25s 后没有交互                                                 | 淡出关闭；鼠标悬停期间暂停计时     |

**触发放在 Rust 侧**（`game_state_monitor` 的阶段变化，和 `hidden_mmr::collector::on_phase_change` 放在一起），
不由主窗口前端发起。原因：主窗口最小化后 WebView2 会节流定时器，靠前端 watch 阶段再开窗口不可靠。

## 窗口

- label `postgame-toast-{gameId}`，每局一个，开新的之前关掉旧的（同 label 立刻重建会撞上异步关闭）。
  不走路由：`Framework.vue` 按 label 直接渲染 `views/PostGameToast.vue`，并跳过 `useGameState`、缩放、启动弹窗、
  云同步等主窗口逻辑。
- `decorations: false`、`always_on_top: true`、`skip_taskbar: true`、`resizable: false`、
  **不抢焦点**：`focused(false)` + `focusable(false)`（tauri 2.11 已提供）。不能打断玩家点「再来一局」，这一条是硬要求。
- 卡片 340×184 CSS 像素。Windows：透明窗口，四周多留 20px 给自绘投影，窗口贴住工作区右下角（工作区已经扣掉任务栏，
  和 WeGame 一样贴在托盘上方）。mac：项目没开 `macos-private-api`，窗口不能透明，改为窗口 = 卡片大小、系统投影、离 Dock 16px。
- 先隐藏创建，复盘模型（无时间线版，很快）就绪后页面自己 show；90s 内取不到、重开局、模型构建失败都直接关，玩家什么都看不到。
- capability：`default.json` 的 `windows` 加上 `postgame-toast-*`。

## 内容

弹卡**自己取数据**：在自己的 webview 里跑 `get_ended_game` → `get_game_by_id` → `useReviewModel`
（`usePostGameReport.loadEndedGameReport()`，与对局页战报同一套加载逻辑），
不依赖主窗口推送（同样是因为主窗口可能被节流）。多出的几次 LCU 请求代价很小。

为了保持先猜再揭晓：**还没标注时，弹卡上不出现 AI 的结论**。

```
┌──────────────────────────────────────┐
│ 胜利 · 亚索 12/3/7 · +21 LP       ✕ │
│                                      │
│ AI 已判出本局最关键和最犯罪的人，    │
│ 你先猜猜？                           │
│                                      │
│ [ 去猜一下 ]          [ 看完整战报 ] │
└──────────────────────────────────────┘
```

如果已经标注过（比如在复盘页标过），就直接揭晓：

```
┌──────────────────────────────────────┐
│ 失败 · 被连累 · -18 LP            ✕ │
│ 9 次阵亡，本人责任只算 4 次          │
│                                      │
│ [ 复制战报图 ]        [ 看完整战报 ] │
└──────────────────────────────────────┘
```

- 「去猜一下」/「看完整战报」：主窗口 show、取消最小化、获取焦点，跳到对局页（战报所在位置），然后关闭弹卡。
  这时玩家主动点了按钮，抢焦点是可以的。
- 「复制战报图」：在弹卡 webview 里离屏渲染 `ShareCard`，复用 #206 的导出逻辑；完成后按钮变成「已复制」，2s 后关闭。
- 本地标注还没查到时短暂显示「AI 复盘生成中…」，按钮只有「看完整战报」。
- 复制出的战报图默认隐藏召唤师名（弹卡上没有开关）。
- 没有国服基准（`!model.hasBaseline`）时不显示「去猜一下」，直接走已揭晓的样式。

## 视觉

弹卡是玩家对这个工具的第一印象，又贴在 LOL 客户端旁边，质感不能比客户端差。原则：**像游戏里的东西，不像系统通知**。

### 底图与层次

- **英雄原画打底**：用本局英雄默认皮肤的居中原画（1280×720）铺满，`object-position` 偏右，
  让英雄露在右半边。左侧叠一层渐变（`#0b0e14` 不透明 → 78% 处全透明）保证文字可读。
  asset 协议新增 `splash` 类型（`asset://…/splash/{championId}`）。原画路径不能按 id 拼——LCU 和 CommunityDragon
  都已经把 `v1/champion-splashes/{id}/…` 换成按英雄名组织的 `ASSETS/Characters/…`（实测旧路径 404），
  所以先取英雄详情 `v1/champions/{id}.json`，读 `skins[0].splashPath`。详情与图片都是 LCU 优先、镜像兜底，走现有磁盘缓存。
  原画取不到时退回深色底加大号英雄头像。
- **圆角 12px**，1px 内描边，颜色取口吻色、透明度 35%，再加一层柔和投影（`0 12px 32px rgba(0,0,0,.45)`）。
  Windows 上窗口四周多留 20px 透明边给投影。
- **口吻色和 #206 战报图一致**：炫耀金 `#f5b544`、洗冤蓝 `#6cb6ff`、平常灰 `#b4bccb`、自嘲橙 `#ff7a59`。
  弹卡和战报图看起来是同一套东西。

### 文字

- 中文用系统字体（Windows 是 Microsoft YaHei UI，mac 是 PingFang SC）。
- **数字（KDA、LP）用 Oswald**：应用已经打包了这个窄体（`.font-number`），两端一致；缺失时退回 Bahnschrift / DIN。
  统一 `font-variant-numeric: tabular-nums`。
- 层级只有三级：顶行（胜负 · 英雄 · KDA · LP）12~13px，主句 17px 粗体（揭晓后标签 24px），按钮 13px。

### 两种状态

**未标注（钩子）**：主句「AI 已圈出本局 **最关键** 和 **最犯罪** 的人」（两个词分别用金色、橙色），
下方一排 5v5 共 10 个英雄小头像（22px），去色压暗，己方在左；两队中间一个发光的「?」。
不在具体头像上标问号——那等于泄露了 AI 选的位置。这一排就是「去猜一下」的视觉钩子。未揭晓时强调色用中性的冷蓝，不暗示结论。

**已揭晓**：去掉头像排，主句换成事实（如「9 次阵亡，本人责任只算 4 次」），标签用口吻色的胶囊。
Carry 时标签是金色渐变字。

### 动效（全部一次性，不循环）

- 进场：从下方 12px 处上滑并淡入，220ms，`cubic-bezier(.2,.8,.2,1)`。
- Carry 进场时，标签上扫过一道高光，600ms，只扫一次。
- 底部一条 2px 的口吻色进度条，25s 内从满缩到空，就是自动关闭的倒计时。悬停时暂停。
- 离场：V1 直接关窗口，不做离场动画（要先播完动画再关窗，收益小）。
- 系统开启了 `prefers-reduced-motion` 时，只保留淡入淡出。

### 按钮

主按钮用口吻色实心、深色字；次按钮用透明底、白色 70% 字，悬停时提亮。高度 30px，圆角 8px。
✕ 平时 40% 透明度，悬停卡片时才完全显示。

### 验收

开发用演示页 `share-demo.html`（`npm run dev` 后打开 `http://localhost:1420/share-demo.html`，不进正式构建）
把弹卡和战报图的全部状态摆在一页：未标注、已揭晓 × 四种口吻、Carry、模型未就绪、原画缺失兜底、复制成功；
地址带 `?export` 时再用 modern-screenshot ×3 真实导出一遍，检查渐变字、原画在 PNG 里是否保真。
另外在 Windows 真机上截一张贴着任务栏的实际效果。

## 战报图视觉升级（同一 PR）

战报图是真正发到群里的东西，这次一起升级，和弹卡用同一套视觉：

- 顶部原画区（至少 172px，正文用不完的高度都给它，事实少的卡原画更大、底部不留白），
  左上胜负胶囊、右上 `RANK ANALYSIS` 字标，下方 44px 大号标签（Carry 金色渐变字）+ 一句人话。
- 本人一行：头像（口吻色描边）、英雄 · 位置、26px Oswald 大号 KDA。
- 事实面板：口吻色左边线 + 渐变底；标题有依据时支撑只留 1 条，否则 2 条——
  标题折行 + 依据 + 2 条支撑 + 7 个分项会把页脚挤出 480 高度（演示页实测）。
- 分项改成双列单行，等级条以中线为基准：领先往右、落后往左，比原来从左往右填一眼看得出好坏。
- 时长 / LP / 隐藏分改为胶囊，页脚一行。

## 设置

常规设置里加「赛后右下角弹卡」，默认开启。弹卡上的 ✕ 只关当局，不提供「不再提示」（避免误点后再也看不到）；
想关闭去设置里关。

## 打点

`track_postgame_toast(action)` 白名单映射到 `track_feature`，和 `track_share_card` 一样：

- `postgame_toast_shown`
- `postgame_toast_guess`（点「去猜一下」）
- `postgame_toast_open`（点「看完整战报」）
- `postgame_toast_copied`
- `postgame_toast_closed` / `postgame_toast_expired`（手动关 / 超时关）

和 `share_card_*`、标注上传量放在一起看：弹卡上线前后标注率和复制率的变化。

## 风险与待验证

| 风险                          | 处理                                                                   |
| ----------------------------- | ---------------------------------------------------------------------- |
| 弹卡抢了 LOL 客户端的焦点     | Windows / mac 真机验证：弹出期间连点「再来一局」不受影响               |
| WebView2 冷启动慢（几百毫秒） | 结算后客户端本来就要好几秒才能取到对局，冷启动可以接受；不预热，省内存 |
| 多显示器、LOL 客户端在副屏    | V1 固定弹在主显示器；看反馈再决定要不要跟随客户端所在的屏幕            |
| 用户觉得打扰                  | 25s 自动关、进选人立刻关、设置可关；观察 `closed` 和 `expired` 的比例  |
| mac 全屏空间                  | 置顶窗口不一定能出现在 LOL 的全屏 Space 上，mac 上能看到就行，不强求   |

## 测试

- Rust：`should_show`（队列、同局去重）、`toast_position`（工作区右下角、DPI 换算、负坐标副屏）、
  白名单打点、原画路径读取与镜像 URL 转换。
- `PostGameToastCard.spec.ts`：三种状态的内容与按钮、未揭晓时不出现结论、Carry 样式、原画失败兜底、
  超时关闭与悬停暂停。
- `PostGameToast.spec.ts`：模型就绪才亮窗、重开局 / 构建失败 / 超时放弃直接关、已标注直接揭晓、
  无基准直接揭晓、复制走离屏战报图（隐藏名字）后关闭、复制失败可重试、各按钮打点。
- `usePostGameToastNavigation.spec.ts`：主窗口只接受白名单路径跳转。
- 设置开关默认开、读写配置。
- 手动：Windows、mac 各打一局排位，确认弹出位置、不抢焦点、跳转到对局页、复制出的图能在 QQ / 微信里粘贴。
