# 赛后复盘可视化仪表盘 — 设计

日期：2026-11-08
状态：已口头批准（布局 = A 战报仪表盘；位置 = 对局详情窗口新增「复盘」标签页；模块 = 基础 6 块 + 出装对比 + 曲线上点团战 + 异常小标签；图表 = 手写 SVG 组件）。
前置：`2026-11-07-timeline-review-design.md`（时间线事实卡片）、`2026-11-07-player-scoring-design.md`（大盘评分模型），均已实现。

## 背景

用户反馈：复盘「可读性不强」「英雄对位看不出来」「文字表达不够直观」。同时实测 qwen-flash 即使拿到带责任标注的材料，仍会把「自身问题」的阵亡写成「被连累」。结论：关键信息改由代码确定性地画出来，AI 文字缩成几句点评作补充。

## 目标与非目标

目标：打开对局详情的「复盘」标签即可看到对位、分项水平、经济走势、阵亡责任、出装差距；图表不依赖 AI，打开即显示；AI 点评几句话、引用可点击定位。

非目标：回放跳转；跨局复盘；新的评分/标签逻辑（全部复用评分模块）；引入图表库。

## 页面结构（自上而下）

1. **标题行**：胜负、队列、时长、击杀比；一句系统生成的胜负关键（复用 `scoredAttribution` 的 winReason 骨架，人话版）。
2. **① 对位总览**：有分路模式按上/野/中/下/辅五行，左蓝右红；每人头像、英雄名、KDA、标签徽章；中间列为 14 分钟对位经济差（以蓝方为正，有时间线才显示）。无分路模式（大乱斗/海斗）改为两队各 5 人并列，按总分排序。点任意玩家切换下方所有模块，当前选中行高亮，默认选中本人。
3. **② 个人卡**：英雄、位置、标签、「大约在同位置前/后 X%」；五项（辅助含视野、无分路模式按其权重项）水平条——中线为同英雄同位置国服平均，向左红、向右绿，长度按分项值截断到 ±3；每条下一行等级词 + 1~2 个具体数据（来自 `plainScore`）。异常小标签：大招晚点、第一件传说装比对位晚 ≥2 分钟等（来自 S/I 卡）。
4. **③ 经济曲线**：两队经济差逐分钟折线（上 = 蓝方领先）；标记：⚔️ 团战（F 卡）、🐉 资源（大龙/小龙/先锋/虚空）、选中玩家的阵亡点（颜色 = 责任）。悬停显示时刻与经济差；点 ⚔️/🐉 弹出详情卡（人头比、参战/缺席、团后资源）。
5. **④ 阵亡与责任**：选中玩家每次阵亡一行：时间、地点、击杀者、责任徽章（自身问题 / 部分责任 / 情有可原 / 团战中 / 其他）；末行分类计数。
6. **⑤ 阵亡地图**：SVG 简化峡谷（三路 + 河道 + 基地），阵亡点按坐标缩放、颜色 = 责任；与列表悬停联动。无分路模式与无时间线时隐藏。
7. **⑥ 出装对比**：两条时间轴（选中玩家 vs 对位，无分路模式 vs 全场同类中位），标出传说装与鞋成型时间，第一件传说装差距标注。
8. **⑦ AI 点评**：打开标签自动生成整局点评（几句话）；切换玩家不自动重跑，显示「生成该玩家点评」按钮（单人模式）。`[D4]` 等引用可点击定位到对应阵亡/团战，并保留悬停原文。

颜色语义统一：蓝/红方固定色；责任红（自身问题）/黄（部分）/绿（情有可原）/灰（团战中/其他）；标签徽章与现有锐评配色一致。沿用应用 CSS 变量，亮/暗主题均适配。

## 架构

### 视图模型（纯函数）

`services/ai/review/buildReviewModel.ts`：

```ts
buildReviewModel(snapshot: MatchSnapshot, scores: PlayerScore[], timeline: SlimTimeline | null): ReviewModel
```

`ReviewModel` 包含：`header`、`lanes`（有分路：5 组 {pos, blue, red, goldDiff14|null}；无分路：两队列表）、`players: Record<pid, PlayerView>`（标签、分位短语、分项 {key, value, level, detail}、异常标签、阵亡列表 {time, zone, killers, responsibility, x, y}、出装 {name, kind, minute}）、`goldCurve`（点列 + 标记 {kind, minute, refId, detail}）、`fights`（详情）。只读组合已有模块：`scorePlayers`/`scoreSnapshot`、`plainScore`、`deathAttribution`、`buildTimelineCards`、`laneOpponent`、`labels`。不新增判断逻辑。

### 组件（`components/record/review/`）

`ReviewTab`（容器、选中玩家状态、加载 AI）、`MatchupBoard`、`PlayerScoreCard`、`GoldCurve`（含弹出卡）、`DeathList`、`DeathMap`、`ItemTimeline`、`AiCommentary`。全部手写 SVG/CSS，无新依赖；头像用 `useAssetUrl`。

### 接入

- `MatchDetailModal.vue`：新增「复盘」标签页（与记分板并列），原「AI 复盘」按钮改为切到该标签；删除 `MatchAIPanel.vue` 弹窗。
- `useMatchAIAnalysis.ts`：改为服务标签页（整局自动、单人按需），保留现有缓存、运行代次、降级提示逻辑。
- 时间线：标签打开时复用 `fetchMatchTimeline`（已有按局记忆）；未就绪前图表区显示骨架，就绪后渲染。

### 降级

- 无时间线：对位总览（无经济差列）+ 个人卡（无对线项）照常；曲线/阵亡地图/出装对比隐藏，提示「本局时间线不可用」；阵亡列表仅显示「阵亡 N 次（无时间线，无法细分）」。
- 无分路模式：对位总览改两队并列；无阵亡地图；出装对比改为对全场中位。
- 评分基准缺失的队列（如斗魂竞技场）：个人卡只显示本局相对数据与标签，不显示分位。

## 测试

- `buildReviewModel` 单测：两份入库匿名回归 fixture（单双排）+ 构造的无时间线 / 无分路输入；断言对位分组、等级词、阵亡分类计数、曲线点数与标记、出装时间、默认选中本人。
- 组件测试：点击切换玩家各模块同步；降级显示；曲线点击弹出卡；`[D4]` 点击定位。
- 真机验收：dev 模式打开单双排、大乱斗、海斗各 1 局截图核对；亮/暗主题各看一次。

## 风险

- 坐标→小地图映射是近似（与 `zoneOf` 同一坐标系，地图 ~14870 见方）。
- 详情窗口宽度不足时的响应式：两列区（对位/个人卡、阵亡/地图）在窄宽度下改为纵向堆叠。
