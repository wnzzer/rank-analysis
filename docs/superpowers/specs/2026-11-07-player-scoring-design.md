# 赛后复盘：基于国服大盘基准的玩家评分模型 — 设计

日期：2026-11-07
状态：三段设计已口头批准（基准来源 = 自建国服大盘；粒度 = 英雄×位置×队列，样本不足回退位置；权重 = 手工设定的可调常量，数据只做基准/阈值/合理性检查；取消 Stage 1 模型调用）。
前置：`2026-11-07-timeline-review-design.md`（时间线事实卡片，已实现）。

## 背景与问题

用户盲评与核对原始数据发现，现有判定（即使 Round 3 已改为 TS 规则判定）有两个根本缺陷：

1. **没有基准**：「伤害占比 30%」只在本局 10 人里相对比较，不知道该英雄该位置正常水平。
2. **分不清责任来源**：「单线被突破、没队友帮、对面也没人来」本应全责，但现规则只看结果，伤害高就会被洗成「被连累」。

目标：用「国服大盘基准 + 时间线归责 + 数据校准权重」给每位玩家打可拆解的分，标签只由分数决定，模型只负责把分数拆解翻译成人话。

非目标：段位分档（首版不做，靠雪球采样近似同分段）；黑箱模型（GBDT 等）；实时在线更新基准。

## 试采结论（2026-11-07，影响设计的事实）

- SGP `match-history-query/.../player/{puuid}/SUMMARY` 可查任意玩家，每局含 10 人终局数据；单 token 可跨大区。
- 421 次请求 / 215s / 0 次 429、5xx、401；2000 局 + 300 份 DETAILS 共 29.7MB。
- **单双排、灵活排位的 SUMMARY 带完整 `teamPosition`**（本地 LCU 没有），分路无需推断；大乱斗、海斗为空（按英雄键）。
- 无 `summoner1Id/2Id`，用 `spell1Id/spell2Id`。
- 单种子雪球采样下：420 = 1522、2400 = 382、440 = 92、450 = 4 —— 大乱斗、灵活需要额外种子。
- 版本跨度 16.14 ~ 16.22。

## 1. 数据采集与基准库

### 采集器（`rank-analysis-app/scripts/baseline/collect.mjs`，已实现试采版）

- 从当前用户出发 BFS：每人 SUMMARY `count=20`，10 人 puuid 入队；gameId 去重；只收 420/440/450/2400 且 ≥5 分钟。
- DETAILS 抽样（优先 420，其次 440），gzip 存盘。
- 限速 2 req/s；429/5xx 指数退避（30s 起、上限 10 分钟），连续 5 次失败优雅停止；断点续采；token 每 10 分钟或 401 时重取。
- 原始数据 `scripts/baseline/raw/` 不入库。
- **补充（待做）**：`--seed-queue 450|440` 模式——从种子玩家近 100 局中优先展开含目标队列的对局，补足大乱斗/灵活样本。
- **规模**：已采 SUMMARY 2 万局（420=12397/2400=6216/440=1178/450=209）+ DETAILS 2000；补采只针对排位（420/440），目标排位共约 4 万局、DETAILS 6000；其他队列顺带。

### 基准库（入库产物，不含任何个人数据）

- 路径：`rank-analysis-app/src/data/baseline/baseline.json`（随 app 打包，几百 KB）。
- 结构：`{ meta: { builtAt, versions, sampleGames, perQueue }, cells: { "<queue>|<position>|<championId>": Stats, "<queue>|<position>|*": Stats } }`；`Stats = { n, metrics: { <name>: { mean, std } } }`。
- 回退：`n < 50` 的英雄格不收录，查询时退回 `<queue>|<position>|*`；大乱斗/海斗 position 为 `*`。
- 终局指标（SUMMARY）：dpm、gpm、csm、kda、killParticipation、deathsPerMin、visionPerMin、damagePerGold、objectiveDamagePerMin、ccPerMin。
- 时间线指标（DETAILS，仅有分路队列）：goldDiff10/14、xpDiff10/14、csDiff10/14、soloDeathRate（对线期被单杀/次）、gankedDeathRate、isolatedDeathRate、fightAbsenceRate、firstDeathMinute。
- 构建脚本：`scripts/baseline/build.mjs`（读 raw，产出 baseline.json 与分位数阈值 `thresholds.json`；权重是代码常量，见 §3）。指标计算与 app 端共用同一份 TS 定义（构建脚本通过 vitest eval 配置调用 TS，避免两套口径）。

## 2. 分项打分与死亡归责（TS 纯函数，`services/ai/shared/scoring/`）

### 归一化

`z(metric) = (value − mean) / std`，基准取英雄格，缺失回退位置格；`std` 下限 1e-6；z 截断到 [−3, 3]。死亡类指标取负号（越少越好）。

### 死亡归责（每次阵亡判类型 + 本人责任系数）

| 类型 | 判定（时间线） | 责任 |
|---|---|---|
| 单杀 | 击杀者仅对位、无助攻 | 1.0 |
| 孤立阵亡 | 死前最近队友 > 2000 码，且非在本人线被单杀 | 1.0 |
| 被抓 | 对面打野/中单/辅助参与，地点在本人分路区域 | 0.5 |
| 团战阵亡 | 落在团战卡内且队友未先崩 | 0.6 |
| 队友先崩 | 阵亡前 30 秒内 ≥2 名队友已阵亡 | 0.3 |

优先级自上而下取第一类。无时间线时所有阵亡按 0.8 计（保守）。

### 分项（各为若干 z 的均值，再由 §3 的权重加总）

- **对线**：goldDiff14、xpDiff14、csDiff14 的 z，减去 `Σ(对线期阵亡责任) × 单杀惩罚`。「单线被突破无人帮」表现为差值 z 低 + 阵亡全为单杀 → 无任何减责项。
- **团战**：killParticipation z、团战缺席率 z（负）、团战内先死次数（负）、damagePerGold z。
- **死亡质量**：`−Σ(责任 × 后果)`，后果 = 1 + 死后 60s 丢失资源数 + 送出终结赏金/300。
- **发育**：gpm z、csm z（打野、辅助用本位置基准）。
- **资源**：objectiveDamagePerMin z、参与的龙/大龙/塔数。

### 减责证据（只用于给低分玩家减责：把「犯罪」改判为「被爆」）

1. 本人阵亡中「被抓」「队友先崩」占比 ≥ 50%；
2. ≥2 名队友对线分 < −1.0（对线崩盘）。

伤害高、KDA 尚可**不构成**减责理由。

## 3. 权重、标签映射与验证

### 权重（手工设定的可调常量，2026-11-07 用户决定不用逻辑回归）

用户否决逻辑回归：胜负是整队结果（学到的是「赢家长什么样」而非「谁负责」），且分项高度相关、系数不可解释。改为手工权重，写在 `services/ai/shared/scoring/weights.ts`，按位置一组，每组和为 1：

| 位置 | 对线 | 团战 | 死亡质量 | 发育 | 资源 | 视野 |
|---|---|---|---|---|---|---|
| 上单 | 0.30 | 0.20 | 0.25 | 0.15 | 0.10 | — |
| 打野 | 0.10 | 0.25 | 0.20 | 0.15 | 0.30 | — |
| 中单 | 0.25 | 0.25 | 0.25 | 0.15 | 0.10 | — |
| 下路 | 0.25 | 0.25 | 0.20 | 0.20 | 0.10 | — |
| 辅助 | 0.20 | 0.30 | 0.25 | — | 0.10 | 0.15 |
| 大乱斗/海斗 | — | 0.50 | 0.30 | 0.20（伤害/经济比） | — | — |

- 打野「对线」= 与对面打野的经济/经验差 + 野区资源差。
- 辅助「视野」= visionPerMin z、控制守卫数 z。
- 无时间线的局：对线分项缺失时，其权重按比例分摊给其余分项；死亡归责按 0.8。

数据只用于：基准（§1）、分位数阈值（下文）、合理性检查（§验证 1）。

### 总分与标签（只用分数）

- 总分 = Σ w_k · 分项_k（单位：基准标准差）。
- 阈值取语料中同「队列 × 位置」总分的分位数。按优先级自上而下取第一个命中的标签（2026-11-07 用户确认的拆分）：
  - 尽力：胜方且总分 ≥ P80；
  - 被连累：败方，且（总分 ≥ P70，**或**总分为本队唯一最高（并列不算）且 ≥ P40）——**打得好的输家不需要减责证据**（个人达标而队伍输即「被连累」本义；2026-11-07 用户选择「绝对 + 相对」混合口径：队内最尽力者只要不低于大盘中下游即可）。复盘仍须点出其分项短板（如对线落后），不得只夸；
  - 被爆：败方或胜方，总分 < P70 且（对线或死亡质量分项 ≤ P10），**且减责证据成立**（措辞同情）；
  - 犯罪：败方，总分 ≤ P20，且无减责证据（「单线被突破、无人帮、对面也没来」即此类，不洗）；
  - 缚地灵：团战分项 ≤ P10 且发育分项 ≥ P60；
  - 正常：其余。
- 减责证据仅用于给**低分**玩家减责，不用于判定高分玩家。
- 必出名单沿用 Round 3（本人、各队击杀/死亡第一、所有非正常），上限 7。

### 喂给模型的材料

每位点名玩家：总分与分位、各分项贡献（如「对线 −1.4｜死亡质量 −0.9｜团战 +0.3」）、死亡归责明细（如「[D3] 14:32 单杀，全责」）。规则：标签与结论只能照抄；措辞立场随标签。

### 分路来源

本地 LCU 战绩无可信分路，现有 positionAssign 推断在真实对局里会把中单/下路互换（局B：影流之主↔奥术先驱）。SGP 单局 `{PLATFORM}_{gameId}/SUMMARY` 带 `teamPosition`：拉时间线时一并取回（Rust 侧），按 puuid 回填到快照，覆盖推断值；取不到时才用推断。

### 单次调用（替代 Stage 1 模型调用）

标签、证据、必出名单都由 TS 确定后，Stage 1 模型只剩写 finalCall——取消 Stage 1 调用，finalCall 由 Stage 2 在同一次调用中按标签立场写出。预期总耗时 24s → 8~10s。归因结果（verdicts/evidence/winReason 的骨架）改由 TS 直接生成；winReason 用 T/F 卡与分项差距的模板句，由 Stage 2 润色。

### 验证

1. 合理性检查（语料上，非拟合）：每个「队列 × 位置」胜方平均总分显著高于败方（差值 > 0.3 个标准差）；任何分项与胜负呈反向相关（如「死亡质量越差胜率越高」）时报告并回看指标定义。
2. 回归用例：用户标注的两局——败方 carry（虚空之女 15/9/9、奥术先驱 24/11/15）必须判为「被连累」（不得为「犯罪」或「正常」）；铁铠冥魂 3/11/9 必须被点名且为负面标签；一个「单线被单杀 ≥3 次、无 gank」的构造局必须判负面且无减责。
3. 同局两次运行的标签一致率 = 1.0（确定性）。
4. A/B：V0（现状）vs 评分版，自动指标 + 用户盲评（新版胜率 ≥ 65%，样本 ≥ 16 对）。

## 风险

- 雪球采样偏向种子附近分段——即「近似同分段」，但非全服大盘；在 meta 里记录。
- 版本更迭使基准过时——记录 versions，建议每大版本重采。
- 用户账号高频访问 SGP 的未知风控——限速 + 退避 + 断点；试采零限流。
- 2400/450 无分路且样本少——按英雄键 + 位置 `*` 回退，样本不足时仅用本局相对比较。
