# 英雄榜 v2：单路榜单与表格重画

日期：2026-09-17
分支：feat/rune-recommend
前身：`2026-09-16-champion-tier-list-design.md`（v1，本文只推翻其中「全部分路」与表格外观两处，其余仍然有效）
修订：2026-09-18 按落地实现回填——正文描述的是最终实现，初稿里被真机验收推翻的四处记在文末「实现时的偏离」。

## 背景

v1 上线后在真机上一看就露馅了两类问题。

**排序是乱的。** 默认排序是「T 级 → 排名」，但 OP.GG 给的 `rank` 是**分路内**的名次。「全部分路」把五条路混进一张表，T1 段里五条路的第 1、2、3 名交替出现，胜率列于是跳成 52.3 → 52.0 → 51.4 → 51.3 → 51.7 → 51.1 → 52.9。用户看到的结论是「这榜根本没排序」。这不是显示 bug，是口径错误：T 级和排名都只在一条路内可比，跨路混排无论怎么排都是关公战秦琼。

**「全部分路」名不副实。** 接口给 267 条（173 个英雄 × 各自打的分路），榜上只显示 173 条——每个英雄只留主分路那条。亚索的上单、下路数据被吞掉了。

**表格本身信息密度过低。** 英雄名那列宽到 770px，右边一大片空白，三个百分比挤在最右侧；行高 60px，1165px 宽的窗口一屏只有 17 行，57~60 行的单路榜要滚三屏；T 级只是彩色文字，一条路里大半是 T1，看不出分层；右边缘一串绿↑红↓箭头是整张表最吵的地方。

## 目标

榜单永远是**一条路的排行**，默认排序自洽；T 级分层一眼可辨；亮色主题下与战绩页同一套「浅灰画布 → 白卡」材质，不像线表。

## 非目标

- 不动详情抽屉（符文 / 出装 / 加点 / 召唤师技能 / 苦手对位 / ☆记住）。
- 不动后端：`list_champion_metas`、`get_champion_build`、OP.GG 快照与段位切换全部照旧。
- 不做大乱斗榜（同 v1）。
- 不修侧边栏点「英雄」带上 `?name=<自己>` 的脏 query：`handleMenuClick` 给所有导航项统一挂 name，战绩页和对局页要用，单独摘出来是另一件事。

## 决策

### 1. 去掉「全部分路」

分路选择器五项：上单 / 打野 / 中单 / 下路 / 辅助。默认值读配置 `settings.opgg.position`；该键未设置时后端 `zero_value_for_key` 给的是空串（不是 null），空串一律落回 `MIDDLE`。切换时写回（与段位 `settings.opgg.tier` 同一路子，会经云同步）。

代价：想一眼扫全版本强势英雄得切五次。接受——跨路混排给出的是错的答案，不是不方便的答案。

### 2. 「#」列是本路榜位，不是行号

列里显示 OP.GG 的 `rank`，**按任意列排序后都不变**。于是按胜率排序时还能读出「薇古丝胜率全中单最高，但本路只排第 14」——行号给不了这个信息。

### 3. 趋势只标真正的异动

`|Δ| >= 5` 才渲染徽章（↑n 绿 / ↓n 红），其余留空。16.18 实测各路有徽章的行占一到两成（上单 16/59、打野 16/60、中单 11/57、下路 11/41、辅助 5/50）。

被否掉的三版：并进榜位列（`3 ▴12`，信息全留但右边缘仍然花）、只留小三角（丢失幅度）、整列删掉（丢失「谁窜上来了」）。

### 4. 行是卡片，不是画线的表

亮色主题的材质是「浅灰画布 → 白卡 → 淡灰凹面」（`CODE_QUALITY.md`「主题材质规则」）。直接在画布上画横线，暗色看不出问题，亮色一眼就是线表。所以每个英雄一行**小卡**，与战绩页的对局卡同一套材质：

- 卡面 `--surface-card` + 细边 `--glass-border` + 软阴影 `--shadow-sm, --glass-highlight`，圆角 `--radius-md`；
- 行间 4px 留缝，不画分隔线；
- 左侧 3px **T 级色条**（T0 金 / T1 绿 / T2 蓝 / T3 淡灰 / T4–T5 无），呼应对局卡的胜负条；
- 悬浮上浮 1px + `--shadow-md`，按下微缩。

行高 42px，表头 30px（表头只是一行灰色小字标签，不是卡）。

| 列 | 宽 | 内容 |
|---|---|---|
| 榜位 | 44 | `rank`，灰色等宽数字，排序后不变 |
| 英雄 | 120–220 | 24px 头像 + 中文名，超长省略 |
| T 级 | 64 | 徽章：T0 实心金 / T1 绿 / T2 蓝 / T3–T5 逐级淡灰 |
| 胜率 · 登场率 · Ban 率 | 各 `minmax(88px, 1fr)` | 右对齐等宽数字，可点列头排序 |
| 趋势 | 60 | `\|Δ\|>=5` 才出徽章 |

英雄列封顶 220px，富余宽度分给三个指标列——否则 1fr 全给名字列，右边空一大片。

**滚动**：工具栏（分路 / 段位 / 搜索 / 刷新）固定，只有表格滚动；表头吸附在表格滚动容器顶部。两个实现细节必须守住：

- 吸附表头的底色必须不透明（`--bg-base`）。`--surface-card` 在暗色是半透明叠加层，拿它做底，行会从表头字底下透出来。
- 表格是竖排 flex 的滚动容器，行与表头必须 `flex: none`。否则内容超高时浏览器先把每行压到最小高度（头像那 24px）才开始滚。

颜色一律走主题 token，不写死 `rgba(255,255,255,…)`，不给 `.theme-light` 打补丁（`src/theme/styleRules.spec.ts` 有守卫）。

### 5. 状态

- 加载中：8 行骨架卡，与真实行同高同列宽。
- 快照为空：「数据未就绪 / OP.GG 数据还没拉到，点「刷新」重试」。
- 搜索无结果：「没有匹配的英雄」。

## 实现

### 数据层 `components/champions/championTier.ts`

- `toRows(metas, position, nameOf)` 删掉 `'all'` 分支与「主分路优先」的 Map 去重，只做 `metas.filter(m => m.position === position)`。`position` 不再接受 `'all'`。
- 新增 `TREND_MIN_DELTA = 5` 与 `notableTrend(trend): Trend | null`——`|delta| >= 5` 返回原 trend，否则 `null`。`trendOf` 不动。
- `filterRows` / `sortRows` 不动。默认档仍是 `T 级 → rank`，此时同路内比较，口径自洽。

### 展示层 `components/champions/ChampionTierTable.vue`

模板与样式重画（自绘网格不变，仍不用 `n-data-table`）。props 不变（`rows` / `loading` / `sortKey` / `sortDesc`）；每行带 `row-tier-N` class 给左侧色条上色；组件自身是滚动容器。

### 页面层 `views/Champions.vue`

- `POSITION_OPTIONS` 去掉 `all`。
- `onMounted` 读配置定初值；`position` 变化时写配置。
- 页面是不滚动的竖排 flex：工具栏 `flex: none`，表格占满剩余高度并自己滚。

## 测试

**`championTier.spec.ts`**
- 删掉 `'all'` 的两条用例，改为「只返回该分路的行」「同一英雄的其他分路不出现」。
- `notableTrend` 阈值边界：4 → null、5 → 有、持平 / 无上版本数据 → null。

**`ChampionTierTable.spec.ts`**
- 榜位列渲染 `rank` 而非行号。
- 按胜率排序后榜位列的值不变。
- 行带 `row-tier-N` class。
- 趋势徽章只在挪动够阈值时出现。

**`Champions.spec.ts`**
- 默认分路取自 `settings.opgg.position`，缺省 `MIDDLE`。
- 切换分路写回配置。
- 选择器里没有「全部分路」。

## 验收

`npm run check` 退出 0、vitest 全绿、cargo 全绿，外加 dev 版截图：中单默认榜、切一条别的路、按胜率排序（榜位列不变）、搜索、抽屉照旧、**滚动后**（表头不透字、工具栏还在、行高没被压扁）。亮暗两套都要看——线表问题只在亮色下暴露。截图期间不点「☆ 记住」、不切段位、不点主题开关——三者都写配置，会经云同步推到安装版。

## 实现时的偏离

初稿经评审通过后，有四处在真机上被推翻。正文已按最终实现改写，这里留下「原来怎么定的、为什么不行」。

| 初稿 | 落地 | 为什么 |
|---|---|---|
| 三个百分比各配一条 3px 迷你条，按全路最大值归一 | 整套删掉（含 `maximaOf` 与 `maxima` prop） | 三条 × 五六十行太占视野；而且胜率全挤在 45%~53%，从 0 归一每根条都是九成多，本来就没有分辨力 |
| 趋势阈值 `\|Δ\| >= 10` | `>= 5` | 10 是拍脑袋定的。16.18 辅助位一个 ≥10 的都没有，整列是空的，看着像坏了 |
| 行高 38px 的画线表格 | 行高 42px 的卡片行 + T 级色条 | 暗色下没问题，亮色下是线表，与 app 的白卡材质不合 |
| 整页滚动，表头吸附 | 工具栏固定，只有表格滚 | 滚两屏后分路 / 段位 / 搜索就够不着了；吸附表头还因为半透明底色透字 |

教训：**评审用的浏览器 mockup 只画了暗色**，亮色问题到真机才暴露。下次做表格类界面，mockup 要亮暗各一张。
