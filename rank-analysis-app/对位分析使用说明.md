# 选人对位分析

功能分支：`feat/opgg-matchup-panel`。基于上游 `3878348` 开发，保留原 MIT 许可证，提交上游审核；尚未合入正式版本。

## 使用方式

传统双队峡谷选人阶段，在敌方卡片“近期数据”下面点击“对位分析 · 英雄名”。匿名英雄卡也提供入口。右侧进入“英雄对位”内页，左侧和原页面其他功能保留。通过“返回玩家战绩”或“玩家战绩”页签返回，原列表位置和卡片状态保留。

内页支持切换敌方英雄、手动调整分路，以及黄金以上、铂金以上、翡翠以上、钻石以上、大师以上和全部段位。这些是段位集合；与原选人页的 OP.GG 段位设置同步。

“推荐应对”和“谨慎选择”展示候选头像、中文名、整场对位胜率、线杀率和样本数。头像失败时显示固定大小的文字占位。已选/已禁用英雄会标记，数据仍可阅读。本功能不会代替用户选人或锁定。

## 无客户端演示

在 `rank-analysis-app` 目录运行：

```powershell
npm ci
npm run demo:matchup
```

打开 <http://127.0.0.1:1425/matchup-demo.html>。已安装依赖时可省略 `npm ci`。该入口复用正式战绩卡和对位组件，所有玩家和统计明确标注为示例，不连接游戏客户端；头像来自 Riot 公共资源，需要网络，失败有占位。

可以体验段位同步、敌方换英雄、匿名卡、开始对局隐藏入口、浅深主题、头像失败，以及正常/慢响应/无数据/请求失败场景。原应用需要客户端的其他操作在此入口不可用。演示是独立开发入口，不出现在正式产品导航和正常构建中。

正式开发仍使用项目原命令 `npm run tauri dev`。在安装了腾讯英雄联盟客户端的电脑上进入选人阶段，即可试用真实数据和客户端头像。2026-10-29，需求方已使用此前构建的 Windows 自用安装包完成实际体验，反馈效果很好；欢迎维护者切到本分支亲自试用。该反馈不等同于所有异常场景或所有平台均已验收。

## 数据口径

- 使用 OP.GG 全球排位对位接口，不读取国服排行榜。
- 分路是英雄主流分路推测，显式标注且可改；不能确定对手实际分路。
- 分组按敌方列表胜率低于/高于50%，恰好50%不归组。小于200局放到同组尾部，这是本工具的提示规则。
- 显示的胜率来自候选自身详情 `win/play`，不是用敌方胜率取补数。列表和详情可能有不同的统计样本或缓存时间。
- 线杀率来自双方 `lane_kill` 比例，是对线阶段击杀或助攻相关指标，不是单杀率；打野显示“不适用”。缺失数据不补零，真实零胜场可显示0%。
- 每页8项，详情最多同时请求3项。同键请求合并，缓存30分钟；段位、分路、英雄、候选和指定版本隔离。网络失败只使用同键旧缓存并标注“过期”。
- 底部与数字提示展示来源版本和时间。来源无时间时明确注明，不冒充本地获取时间。来源链接有已知英雄别名时打开相应 OP.GG 英雄、分路和段位页面，否则明确进入英雄库。

## 验证和剩余验收

已执行项目 `npm run check`、前端全量测试（1223项通过）、Rust全量测试（507项通过/2项忽略，另有文档测试1项通过/23项忽略）、`npm run build`。检查有120条既有 lint 警告而无错误，构建仍有UI包体积提示。没有为通过检查而关闭规则。

真实 Edge 浏览器核验1000/1200/1600宽度和1200×800窗口、深浅主题、段位同步、匿名卡入口、换英雄、打野不适用、返回滚动/焦点、隐藏区域不可聚焦、Escape与下拉、分页、小样本、头像失败、空数据、失败重试、慢响应及减少动态效果。

2026-10-28真实HTTP检查：阿狸中路/翡翠以上及李青打野/钻石以上，版本16.21。Rust测试使用源字段样本和边界数据验证解析与缓存；这不等于真实客户端联调。

实机状态：需求方于2026-10-29确认已经实际使用，体验效果很好。尚未提供逐项客户端验收记录，因此匿名/非匿名切换、共享段位持久化与失败恢复、外部链接打开及进入游戏后的退出行为，仍保留为维护者审查和试用时的重点；macOS 未在本地验证。本功能尚未作为上游正式版本发布。
