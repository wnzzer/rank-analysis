## PART A · 现状诊断

> v1.0 已基于 codegraph 全量审读并逐条附代码证据，此处只留结论索引；工程迁移时仍以 v1.0 §1 的问题清单为核对表。

| 类别 | 核心结论 |
|------|----------|
| 设计系统 | token 双轨（`global.css:30-33 vs 52-61`）、`!important` 战争（`global.css:202-230`）、z-index 无治理、9px 字号越界 |
| 壳层 | 36px 标题栏塞 5 类元素（`Header.vue:2-111`）；侧栏状态灯兼职导航（`SideNavigation.vue:51-84`）；品牌仅字母 R |
| IA | 无主页，落地即战绩列表；设置双层侧栏嵌套（`Settings.vue:2-31`）；Growth 风格断裂（`Growth.vue:2-74`） |
| Gaming | 情报横幅 9 段裸堆无容器（`Gaming.vue:135-239`）；核心入口是 opacity 0.6 悬浮钮（`:869-885`）；AI 报告锁在 modal |
| Record | 工具栏 7+ 控件混排（`MatchHistory.vue:4-64`）；详情 8 tab 平铺内嵌展开（`MatchDetailInline.vue:440`） |
| Overlay | 硬编码颜色、位置固定不可配（`OverlayView.vue:53-128`） |

**诊断总纲**：这不是"丑"的问题，而是**没有设计身份、没有场景分级**——选人期 30 秒的决策工具和赛后 10 分钟的阅读工具长着同一张脸。全新设计必须同时回答这两个问题。

## PART B · 全新设计愿景

### B1 三个风格方向

#### 方向 A · 奥术金工 Hextech Forge（推荐）

- **一句话**：海克斯水晶 × 精密仪器。像一件为召唤师打造的暗色测量仪器，而不是一个网页。
- **色彩**：蓝黑基底 `#0a0e14`；主强调**金**（`#d4a548 → #f0c96b` 渐变，用于结论/激活/关键数值）；辅助青蓝 `#4cc2ff`（信息/链接）；胜负语义绿 `#3fbf8f` / 红 `#e05c5c` 降饱和融入体系，不再充当品牌色。
- **形状**：标志性**切角卡片**（hextech 斜切角，clip-path 12px 角）+ 1px 金/灰细描边 + 内衬微噪点。
- **字体**：标题 Bahnschrift SemiBold 宽字距；正文系统栈；数字 Bahnschrift Condensed（已有 `.font-number` 底子）。
- **动效**：「充能」语言——倒计时环、扫光划过、金色辉光呼吸。克制在关键节点。

#### 方向 B · 战术指挥舱 Tactical Deck

- 军用 HUD：纯黑底、荧光琥珀 + 磷光绿数据、等宽数字、四角括号框线、网格背景、扫描线动画。
- 极致密度，硬核感最强；风险：审美窄众，长时间阅读页（复盘/成长）易疲劳。

#### 方向 C · 竞技数据志 Editorial Arena

- 体育数据媒体风（FiveThirtyEight × op.gg Premium）：亮色纸面为主打（反转现有深浅主次），大号标题、图表化叙事、红蓝队色主导、极简卡片。
- 最耐看、差异化最大；风险：与"游戏中挂机工具"的场景气质有距离。

### B2 推荐定稿：奥术金工 Hextech Forge

**理由**：

1. 场景契合：暗色对局环境友好；金色与 LoL 生态（海克斯/金币/段位）天然同源；
2. 区分度：竞品 op.gg 是白底数据站、LeagueAkari 是绿玻璃工具——金工暗器无人撞型；
3. 可扩展：切角卡片 + 金描边是一套可复制的几何语法，从 overlay 到设置页都能统一；
4. 语义安全：胜负绿红退居语义位，品牌金不与任何数据语义冲突（现方案用 win 绿当品牌色，胜负一多满屏"品牌色"，这是现状显脏的根因之一）。

**双主题策略**：深色为第一主题（对局场景）；浅色主题对应转译为「羊皮纸金工」——暖白纸底 `#f5f1e8` + 深金 `#8a6420` + 墨青文字，同一几何语法换材质。

## PART D · 设计系统 v3

### D1 Token 三层制（在 v1.0 基础上换血）

```
primitive: --hx-gold-300..700 / --hx-cyan-... / --hx-ink-...
semantic : --bg-base #0a0e14 / --bg-surface / --bg-raised
           --brand(-strong/-soft) 金系 / --info 青 / --win / --loss / --warn
           --space-* / --radius-* / --font-size-xs..2xl(≥10px)
           --dur-* / --ease-standard|--ease-spring（唯一双轨）
           --z-content|sticky|dock|modal|toast
shape    : --clip-corner: polygon(...) 切角卡片专用
```

- 删除 v1 现存全部旧别名（`--transition-*`、`--ease-out-expo`、`--semantic-win` 作品牌色的用法）；
- `buildThemeOverrides()` 只读 semantic token（修 v1.0-D6）；
- 全局禁令入 CODE_QUALITY.md：组件内禁 hex/rgba、禁 ad-hoc z-index、禁 !important（白名单除外）。

### D2 组件规范（`components/ui/`）

v1.0 清单全量保留（PageHeader / SectionCard / Toolbar / StatChip / EmptyState / DangerButton / KeyHint / CommandPalette），新增：

| 组件 | 用途 |
|------|------|
| `CornerCard.vue` | 切角卡片基座（clip-path + 描边 + 噪点材质插槽） |
| `ChargeRing.vue` | 充能环（倒计时/进度通用，Gaming 结论带与收集进度共用） |

## PART E · 高保真原型阶段

**先稿后码，是"全新"与"翻新"的分水岭。**

- **载体**：仓库内 `design/prototype/` 独立 Vite 入口（不进打包），直接消费 v3 token CSS——原型即规格，定稿后 token 文件原样迁入 `src/`。
- **覆盖画面**（8 屏 2 时刻）：
  1. 主页（已连接 / 未连接两态）
  2. Record 宽屏双栏 + 窄屏内嵌展开
  3. Gaming 常态 + **指挥舱·选人倒计时中**（关键时刻）
  4. 赛后复盘详情栏（关键时刻）
  5. Growth / Library / Settings / Overlay
- **交互深度**：可点击切换 主题（金工暗/羊皮纸亮）× 密度（normal/compact）× Gaming 双模式；结论带倒计时环真实走秒。
- **完成定义（DoD）**：组织 3~5 人走查会，按「3 秒结论可达 / 一眼认出风格 / 两主题无破相」三条验收；走查意见回灌 token 与蓝图后才允许开工 P0。

## PART G · 度量、验收与风险

### 验收指标

| 维度 | 指标 | 目标 |
|------|------|------|
| 效率 | 选人期找到当前建议用时（5 人走查录屏） | ≤3s |
| 效率 | ⌘K 搜人→进战绩全程键盘 | ≤5s |
| 识别度 | 盲测认出"这是一个新产品"比例 | ≥80% |
| 一致性 | 组件内硬编码颜色 / ad-hoc z-index / !important | 0 / 0 / −90% |
| 质量 | vitest + `npm run check` | 每阶段全绿 |
| 主观 | SUS 问卷（新旧各一次） | ≥80 |

### 风险与对策

| 风险 | 对策 |
|------|------|
| 全新视觉不被老用户接受 | Gaming/壳层走 feature flag 灰度，保留一键回退至旧 UI 一个版本周期 |
| 切角卡片等自定义形状的性能（clip-path 大面积） | 原型期实测 GPU 占用；超预算降级为伪切角（背景 SVG 角贴片） |
| 设计期拉长导致工程观望 | D0/D1 与 P0 token 地基并行；D3 冻结前不动页面代码 |
